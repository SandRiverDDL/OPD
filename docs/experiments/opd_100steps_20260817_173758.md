## 5. Parameter-update diagnosis

为判断旧 run 是否真正有效更新，比较了 `global_step_20` 到
`global_step_100` 的 actor 参数：

| Quantity | Observed value |
|---|---:|
| Actor parameter dtype | `torch.bfloat16` |
| Adam `exp_avg` dtype | `torch.bfloat16` |
| Adam `exp_avg_sq` dtype | `torch.bfloat16` |
| Parameters with changed values | 约0.73% |
| Parameters with unchanged values | 约99.27% |
| Relative local L2 displacement | `1.29e-4` |

这组结果与以下数值路径一致：

```text
bf16 parameter + lr=1e-6
→ 大量 Adam update 小于当前 bf16 ULP
→ 写回参数时被舍入
→ 参数更新稀疏且量化
```

这里的结论不是“模型完全没有训练”，而是：

> 该 run 的有效参数更新极度稀疏，不适合作为正常 FP32 optimizer
> dynamics 下的 `N=1` 对照。

## 7. Interpretation and limitations

### Supported conclusions

- 该 run 的 AIME25 结果在 step40 达到 26.88%，随后没有稳定上升；
- 训练日志显示 top-16 overlap 基本不变；
- checkpoint 检查显示绝大多数 actor 参数没有发生数值变化；
- bf16 参数和 bf16 Adam state 是该异常行为的强候选原因。

### Not established by this run

- 不能由此独立估计 `N=1` 相对 `N=4` 的真实影响；
- 不能把 AIME25 的 step40 峰值解释为稳定最优 checkpoint；
- 不能把 MATH-500 的不同 `max_tokens` 结果放在同一条训练曲线上；
- 不能排除数据顺序、数据内容和训练时长对结果的额外影响。
